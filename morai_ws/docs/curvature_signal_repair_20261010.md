# 곡률 주행·교차로 신호 수정 — 2026-10-10

## 적용 내용

- 위치와 자세는 기존 GPS/IMU EKF를 사용한다. 속도 제어는 신선한 `/Ego_topic`의 차량 속도(m/s)를 사용한다. 필요한 Ego 속도가 0.5초 넘게 지연되면 가속하지 않고 정지한다.
- 최고 목표속도는 35 km/h, 지정 신호 교차로 접근 목표속도는 최대 30 km/h다. 곡률이 큰 구간에서는 그보다 낮춘다. 이 값은 실제 속도의 물리적 보장을 뜻하지 않는다.
- MGeo 곡률 속도 프로파일의 전방 최저 속도를 먼저 반영한다. 목표속도가 내려가면 추가 시간 지연 없이 제동 오차에 반영한다. 목표속도 이상에서 남은 가속 적분항과 가속 페달이 유지되지 않게 한다.
- 조향에서 Pure Pursuit의 횡방향·방향 오차 보정량을 유지하고, 경로 곡률 선행 보정을 더한다. 좌우 연속 커브에서 반대 방향 선행 보정과 CAM1 보정이 현재 경로 조향을 풀지 않도록 제한한다.
- 정지선 위치는 지정된 MGeo 교차로에서 미리 확보한다. YOLO가 가까이에서 신호를 인식할 때까지 제동을 미루지 않는다. CAM1 정지선의 위치 일치도 확인한 뒤 신호 통과를 허가한다.
- 정차 목표는 차량 앞부분이 정지선보다 12 m 앞에 머무는 위치다. 위치/정지선 측정 오차와 차량 제동 응답에 따라 실제 거리는 달라질 수 있다.
- 다음 교차로의 접근 감속이 현재 교차로의 초록 신호 통과 허가를 취소하던 조건을 분리했다.

## CAM4 설정

사용자가 제공한 MORAI 값:

| 항목 | 값 |
| --- | --- |
| 위치 X/Y/Z | 3.43 / 0.01 / 0.61 m |
| Roll/Pitch/Yaw | 0 / 0 / 0° |
| 영상 | 640 × 480 |
| FOV | 90° |

`config/curvature_signal.yaml`에 반영했다. 투영기는 롤 0, 수평 FOV 90°, 정사각형 픽셀을 사용한다. 이 설정에서 초점거리는 320 px다. 실제 영상과 지도 투영의 일치 여부는 현장 진단의 `route_signal_pixels` 및 신호 상자로 확인할 수 있다.

MGeo의 현재 교차로 링크에 연결된 신호등만 영상 시각의 차량 자세로 투영해 선택한다. 다른 교차로 신호와 겹치거나 모순되는 검출은 허가하지 않는다. 같은 경로에 속한 반복 신호등은 공통으로 허용하는 방향을 사용한다. 신호 허가는 서로 다른 원본 영상에서 최소 0.3초 동안 확인되어야 한다.

| MGeo 정지선 경로 거리 | 교차로 경로 방향 | 통과 신호 |
| --- | --- | --- |
| 약 208 m | 직진 | 초록 원형 신호 |
| 약 316 m | 직진 | 초록 원형 신호 |
| 약 437 m | 직진 | 초록 원형 신호 |
| 약 551 m | 우회전, 약 −84.7° | 초록 원형 또는 허용되는 우회전 신호 |
| 약 610 m | 좌회전, 약 +85.2° | 좌회전 화살표; 빨강+좌회전도 허용 |

방향은 해당 교차로를 통과하는 목표 경로의 방향 변화로 계산하고 MGeo 링크 정보와 대조한다. 좌회전 구간에서 초록 원형 신호만 보이면 대기한다. 빨강·노랑·미확인 신호를 단순히 “빨강이 아님”으로 취급해 출발하지 않는다. 이 프로파일은 신호·곡률 주행용이며 전체 장애물/보행자 회피 미션을 포함하지 않는다.

## Ubuntu에 설치하고 실행

먼저 실행 중인 주행 launch를 해당 터미널에서 `Ctrl+C`로 종료한다. 차량은 출발점 또는 정지선 이전에 배치한다. 허가 없이 정지선을 이미 넘은 상태의 `entry_without_current_permission`은 자동으로 해제하지 않는다.

```bash
cd ~/AutoVehicle
git pull --ff-only origin final_ws
cd morai_ws/docker/final_ws
bash run_highway.sh stop
bash install_curvature_signal.sh --config
bash run_highway.sh start
bash run_test.sh turn safe
bash run_test.sh speed 35
bash run_test.sh lane on
bash run_test.sh show 2
bash run_test.sh drive 2
```

- `--config`는 위 CAM4 설정과 교차로 목록을 컨테이너에 설치한다. 기존 파일은 설치기가 백업한다. 이번 적용에서는 생략하지 않는다.
- 설치기는 Python 보조 모듈까지 복사하고 SHA256을 대조한다. 중단된 설치나 서로 다른 실행 파일은 프로파일 2 실행 전에 차단한다.
- 실행 전에 `RUNTIME_MATCH`와 `SIGNAL_CONFIG_MATCH`를 확인한다. 이미지 태그가 같더라도 실제 설치 소스와 설정의 해시를 비교한다.
- `show 2`는 실행 명령을 표시한다. 실제 주행은 `drive 2`에서 시작한다. MORAI는 `AV-ExternalCtrl`로 설정한다.
- 기존 환경에서 CAM1이 CPU로 동작하고 있다면 해당 설정을 유지한다. 이번 수정은 가중치 파일이나 Ultralytics 버전을 변경하지 않는다.

주행 launch를 켜 둔 채 **다른 Ubuntu 터미널**에서:

```bash
cd ~/AutoVehicle/morai_ws/docker/final_ws
bash run_test.sh diagnose 2
```

진단은 설치 revision, 실제/추정 속도, 목표 경로 방향, 선택된 지도 신호 ID·상태, 허용 방향, 정지선 일치 여부, 정차/진입 차단 이유를 출력한다. 영상에 초록이 보이는데 멈춘 경우 이 값을 통해 검출·지도 연결·정지선 확인·진입 상태 중 어느 조건이 막는지 구분한다.

## 확인 범위

소스 및 설치 흐름을 정적으로 검토했다. Windows 작업 환경에서 MORAI/ROS 주행을 실행하지 않았다. 실제 코너 추종, 정차 거리, 신호 투영 일치는 Ubuntu와 MORAI에서 확인해야 한다. 위 파라미터는 수정본의 시작 설정이며 실측 최적값으로 검증된 값은 아니다.
