# MORAI 현재 구성 및 실행 보고서

작성 기준: 2026-09-03

이 문서는 현재 저장소에서 실제로 사용하는 코드와 실행 순서를 한글로 정리한
기준 문서이다. 과거 비교용 workspace는 삭제했으며, 새로운 개발과 실행은
`morai_ws`를 기준으로 한다.

## 1. 현재 구조의 핵심

현재 주행 흐름은 다음과 같다.

```text
MORAI GPS·IMU
    ↓
morai_udp_bridge
    ↓  /gps, /Imu
gps_mgeo_converter
    ↓  /localization/gps
ekf_local_enu
    ↓  /localization/odometry
노이즈 주입·필터
    ↓  /experimental/curvature_filtered_odometry
곡률 기반 속도계획 Pure Pursuit
    ↓  /experimental/curvature_ctrl_cmd
morai_udp_drive_bridge
    ↓
MORAI 차량
```

단, 노이즈 포함 곡률 제어 실험은 기존 주행 제어기와 분리되어 있다. 기존
`/ctrl_cmd` 토픽을 직접 사용하지 않으며, 실험 중에는 `/experimental/*` 토픽만
사용한다.

## 2. 실제 사용하는 주요 패키지

| 경로 | 역할 | 사용 시점 |
|---|---|---|
| `src/localization/morai_udp_bridge` | MORAI GPS·IMU UDP 패킷을 ROS 메시지로 변환 | 실제 MORAI 센서 연결 |
| `src/localization/gps_mgeo_converter` | GPS 위경도를 MGeo local ENU 좌표로 변환 | GPS 위치 생성 |
| `src/localization/ekf_local_enu` | GPS와 IMU를 융합해 차량 pose 생성 | `/localization/odometry` 생성 |
| `src/localization/morai_udp_drive_bridge` | ROS `CtrlCmd`를 MORAI UDP로 송신 | 실제 차량 명령 전송 |
| `src/control/purepursuit_mgeo` | MGeo 경로 기반 기존 Pure Pursuit | 실제 MORAI 주행 |
| `src/experimental/curvature_speed_purepursuit` | 곡률 기반 속도와 노이즈 대응 Pure Pursuit | 현재 새 실험 |
| `src/experimental/stability_stack` | GPS·IMU 원본 노이즈 별도 실험 | 센서 안정성 시험 |
| `src/control/control_mux` | 정상 명령과 안전정지 명령 중재 | 통합 주행 |
| `src/detection` | 카메라·LiDAR·장애물 인식 | 인식 통합 시 |
| `src/common/morai_perception_msgs` | 인식용 사용자 정의 메시지 | Detection 패키지 사용 시 |
| `src/bringup/morai_bringup` | 여러 패키지를 묶어 실행하는 launch | 통합 실행 시 |

## 3. 현재 곡률·노이즈 실험 패키지

### 경로 계산

`planner.py`가 시작할 때 경로를 한 번 읽고 다음 작업을 수행한다.

1. 경로의 연속 중복점을 제거한다.
2. 경로 누적거리 `s`를 계산한다.
3. 세 점 기반 곡률을 계산한다.
4. 곡률에 median smoothing을 적용한다.
5. `v = sqrt(허용 횡가속도 / |곡률|)`로 커브 속도를 계산한다.
6. 가속도 제한과 종료점까지의 감속 제한을 적용한다.
7. 마지막 점을 한 바퀴의 종료점으로 보고 속도 0을 설정한다.

현재 사용 경로는
`data/routes/2026_molit_comp_global_path.txt`이다.

### 노이즈와 필터

`curvature_odometry_noise_filter_node.py`는 Odometry에 다음 노이즈를 추가한다.

```text
위치 표준편차: 0.25m
yaw 표준편차: 0.03rad
속도 표준편차: 0.05m/s
측정 dropout 확률: 2%
```

그 후 다음 필터를 적용한다.

```text
위치 점프 > 5m       → 측정 거부
계산된 순간 속도 > 50m/s → 측정 거부
yaw 변화 > 45도      → 측정 거부
최근 3개 측정        → median 필터
이전 결과와 현재 결과 → EMA(alpha=0.35)
```

filtered odometry가 0.5초 이상 끊기면 곡률 제어기는 정지 명령을 발행한다.

주의할 점은 이 실험 노이즈가 `/gps`, `/Imu` 원본에 직접 들어가는 것이 아니라
`/localization/odometry` 뒤에 들어간다는 것이다. 따라서 현재 실험은 센서 원본
필터 검증이 아니라, 노이즈가 있는 localization 결과에 대한 제어기 내성 검증이다.

## 4. 실행 파일

### 실제 localization 결과 미리보기

먼저 다음 토픽이 정상적으로 발행되어야 한다.

```text
/gps
/Imu
/localization/gps
/localization/odometry
```

그 다음 제어 명령을 발행하지 않는 상태로 실행한다.

```bash
roslaunch curvature_speed_purepursuit \
  curvature_speed_purepursuit_noisy.launch \
  path_file:=/home/<사용자>/AutoVehicle/morai_ws/data/routes/2026_molit_comp_global_path.txt \
  input_topic:=/localization/odometry \
  publish_command:=false
```

확인할 결과 토픽은 다음과 같다.

```text
/experimental/curvature_noisy_odometry
/experimental/curvature_filtered_odometry
/experimental/curvature_noise_filter_status
/experimental/curvature_value
/experimental/curvature_speed_limit
/experimental/curvature_speed_command
/experimental/curvature_steering
/experimental/curvature_progress
/experimental/curvature_goal_reached
```

### 실제 MORAI 제어 연결

미리보기에서 값이 정상인 경우에만 제어 송신 노드를 실험 명령 토픽에 연결한다.

```bash
roslaunch morai_udp_drive_bridge \
  morai_udp_drive_bridge.launch \
  control_remote_ip:=192.168.0.151 \
  control_remote_port:=9093 \
  command_topic:=/experimental/curvature_ctrl_cmd
```

그 다음에만 다음 옵션을 켠다.

```bash
roslaunch curvature_speed_purepursuit \
  curvature_speed_purepursuit_noisy.launch \
  path_file:=/home/<사용자>/AutoVehicle/morai_ws/data/routes/2026_molit_comp_global_path.txt \
  input_topic:=/localization/odometry \
  publish_command:=true
```

이 실험에서는 기존 `perception_control_bringup.launch`를 동시에 실행하지 않는다.
해당 launch는 기존 Pure Pursuit와 control mux를 함께 실행해 명령 흐름이 섞일 수 있다.

## 5. 검증 기준

다음 명령으로 주기를 확인한다.

```bash
rostopic hz /gps
rostopic hz /Imu
rostopic hz /localization/gps
rostopic hz /localization/odometry
rostopic hz /experimental/curvature_filtered_odometry
```

주기 확인 후에는 값과 연결을 확인한다.

```bash
rostopic echo -n 1 /localization/odometry
rostopic echo -n 1 /experimental/curvature_filtered_odometry
rostopic echo /experimental/curvature_noise_filter_status
rostopic echo /experimental/curvature_progress
rostopic info /experimental/curvature_ctrl_cmd
```

정상 판정 기준은 다음과 같다.

- filtered odometry가 계속 출력된다.
- `accepted` 카운터가 계속 증가한다.
- `dropout`과 `rejected_jump`는 간헐적으로만 발생한다.
- 차량 진행거리 `progress`가 갑자기 크게 뒤로 가지 않는다.
- 곡률이 큰 구간에서 속도 제한이 낮아진다.
- 마지막 점에서 `goal_reached=true`가 된다.
- 마지막 점에서 속도는 0이 되고 제동 명령이 발생한다.
- 실험 주행 중 기존 `/ctrl_cmd`에 새 제어기가 연결되지 않는다.

## 6. 설정 파일과 원본 자료

`config/`의 YAML 파일은 공통 설정을 기록하는 기준 자료다. 현재 모든 launch가
YAML을 자동으로 읽는 것은 아니며, 일부 값은 launch 내부의 `<param>` 또는
`<rosparam>`에 직접 정의되어 있다.

`data/routes/`의 경로 파일은 현재 주행에 직접 사용한다. `data/mgeo/`의 MGeo
원본, 규정집, 샘플 시나리오, calibration 자료는 좌표 검증과 문서화를 위한
원본·참고 자료다.
