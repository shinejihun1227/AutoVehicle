# test/roundabout: 교차로 진입 후 신호 소실과 신뢰도 필터

기준 커밋 `e095e970d5a1ac010510c64cde0c092c38a09434`에서 사용자가 요청한 신호 제어만 변경했습니다.
다른 브랜치의 속도·위치 추정·회전교차로 기능은 가져오지 않았습니다.

## 바뀐 동작

- 기존에는 제어 주기 사이에 차가 정지선을 넘고 새 CAM4 프레임이 빨강/노랑으로 바뀌면,
  신호를 먼저 처리해 이전 진입 허가를 취소한 뒤 `entry_without_current_permission`을 고정할 수 있었습니다.
- 이제 기존의 유효한 주행 허가로 앞차축이 해당 정지선을 넘었는지 먼저 확인합니다.
  진입 후 촬영된 빨강·노랑이나 신호등 빈 배열은 그 교차로의 진입 허가를 취소하지 않습니다.
  교차로 안에서는 해당 신호가 사라져도 기존 경로 주행을 계속합니다.
- 진입 전 촬영된 유효한 정지 신호는 계속 적용합니다. 제어 주기 사이에 쌓인 프레임도
  영상 시각의 위치와 대조하므로, 뒤에 온 녹색 프레임으로 이전 빨강을 덮어쓰지 않습니다.
- 녹색 허가 이력 없이 빈 배열만으로 진입을 허가하지 않습니다.
  장애물·유효하지 않은 위치·상위 제어 명령 누락에 대한 정지 조건은 유지합니다.
- 이 교차로의 진입이 확정되면 해당 정지선의 접근 속도 제한도 다시 걸지 않습니다.
  다음 교차로는 별도 신호 허가를 받아야 합니다.

## 신뢰도 기준

신호등은 **confidence > 0.6**만 사용합니다. 정확히 0.6인 검출도 제외합니다.
CAM4 신호 후보 수집 → 시간별 투표 → 경로 투영/가중치 → 신호 확인 단계에 같은 기준을 적용했습니다.
낮은 신뢰도 빨강이 정상 녹색을 취소하거나, 낮은 신뢰도 녹색이 새 출발 허가를 만들지 않습니다.
예전 런치에서 min_confidence를 0.5로 넘겨도 0.6 이하 신호를 다시 허용하지 않습니다.
차량·사람 등 다른 물체 검출과 CAM1 차선/정지선 신뢰도 기준은 변경하지 않았습니다.

## 기존 Docker 실행 폴더에서 적용

현재 주행 터미널을 Ctrl+C로 종료합니다. 아래 첫 경로는 실제 `test/roundabout` 저장소 폴더에 맞춥니다.
개인 env·포트·컨테이너 이름·신호 지도 설정을 다시 복사할 필요는 없습니다.

```bash
cd ~/AutoVehicle_roundabout
git pull --ff-only origin test/roundabout
cd morai_ws/docker/final_ws
bash run_highway.sh stop
bash install_curvature_signal.sh
bash run_highway.sh start
bash run_test.sh show 2
bash run_test.sh drive 2
```

이 변경은 설치 스크립트가 교체하는 Python/런치 파일에 한정되어, 정상 구성된 기존 컨테이너를
새로 만들거나 ROS 패키지를 다시 빌드할 필요는 없습니다. 설치 시 기존 신호 지도 설정을 보존합니다.

## 확인 범위

원본 제어 콜백을 사용하는 오프라인 검사에 다음 상황을 추가했습니다.

진입 전 빨강, 앞선 빨강 프레임 대기열, 허가 없는 빈 배열,
진입 시 장애물 정지, 신뢰도 0.6 경계 및 잘못된 낮은 신뢰도 검출 상자입니다.
검사에서 ROS·UDP·카메라 추론 경계는 대체하므로 실제 MORAI 주행 검증을 대신하지 않습니다.
