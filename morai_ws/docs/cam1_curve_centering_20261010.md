# CAM1 커브 중심 보정 — 2026-10-10

## 동작

MGeo Pure Pursuit 조향에 작은 CAM1 보정을 더한다. 속도 계획과 교차로 신호 판단은 기존 프로파일 2를 사용한다.

기존 방식은 전방 7/14 m 차선으로 계산한 조향을 현재 Pure Pursuit 조향과 섞었다. 두 조향의 관측 거리가 달라 커브에서는 조향을 풀 수 있었고, 이를 막는 조건 때문에 큰 커브에서는 보정 자체가 꺼졌다.

수정본은 다음 순서로 처리한다.

1. `/perception/camera/lane_info`의 원본 관측 시각에 맞는 EKF 위치를 찾는다(최대 50 ms 차이).
2. 그 위치의 MGeo 경로 중심·접선 방향에서 전방 **x=7 m, x=14 m** 교점을 구한다. 경로를 따라 7/14 m 이동한 점과 구분한다.
3. 실제 CAM1 차선 중심과 예상 커브 모양의 차이를 계산한다. 곡률로 생기는 정상적인 휨을 제거한 잔차로 차량 근처 중심 편차와 방향 오차를 근사한다.
4. 이 잔차에 약한 추가 피드백을 적용한다. MGeo의 기본 조향을 감쇠하거나 대체하지 않는다.

잔차 계산에서 양수는 차선 중심이 차량의 왼쪽에 있다는 뜻이다. 왼쪽으로 작은 보정을 준다. 우측 편차에는 반대 방향 보정을 준다. 근사 모델을 사용하므로 큰 경로 불일치는 보정하지 않고 기준 경로 제어로 복귀한다.

## 차선 인식이 충분한 조건

- 양쪽 경계가 실제 관측되어야 한다. 한쪽 누락, 가이드선 대체, 이전 프레임 예측(`coasted`)은 보정 근거로 쓰지 않는다.
- 양쪽 신뢰도가 각각 0.65 이상이어야 한다.
- 양 경계와 중심선이 공통으로 7~14 m를 지지해야 한다. 짧은 검출을 외삽하지 않는다.
- 커브 기울기를 고려한 차선 폭, 경계와 중심선의 일치, 시간에 따른 편차 변화를 확인한다.
- 최초 활성화에는 서로 다른 영상 4개 이상과 최소 0.2초의 안정적인 이력이 필요하다. 활성화 후에는 최신 관측이 유효하고 잔차가 일관될 때 유지한다.
- 확인 이력은 최신 영상 기준 최대 0.8초를 보관한다. CPU 추론 속도가 낮아도 확인 프레임을 확보할 수 있게 하고, 실제 보정 계산은 최근 3개 잔차를 사용한다.
- 최신 원본 시각과 수신 시각 모두 0.4초 이내여야 한다. 과거 영상을 반복 수신해도 새 관측으로 세지 않는다.

차선 메시지 `/detection/lane`에는 양쪽 경계의 실측/예측 정보가 없다. 또한 기존 폭 검사는 커브에서 늘어나는 횡단면 폭을 고정 폭으로 비교한다. 보정기는 같은 CAM1 원본 JSON의 경계점을 직접 사용해 곡선의 수직 방향 폭을 따로 확인한다. 기존 차선 메시지나 신호 제어 계약은 변경하지 않는다.

## 기본값

| 항목 | 값 |
| --- | --- |
| 보정 가중치 | 0.25 × 신뢰도 × 품질 |
| 추가 조향 상한 | ±0.045 rad, 약 ±2.6° |
| 적용 변화율 | 0.06 rad/s |
| 해제 변화율 | 0.10 rad/s |
| 저역 필터 시정수 | 0.35초 |
| 작은 오차 무시 범위 | 중심 편차 0.05 m, 방향 오차 0.01 rad |

인식이 나빠지면 새 보정을 쌓지 않고 남은 보정량을 0으로 줄인다. 조향 부호가 바뀔 때도 0을 거친다. 차량 정지·위치 중단에서는 확인 이력을 다시 확보한다. 최고 목표속도 35 km/h, 교차로 접근 최대 30 km/h, 정차 여유 12 m는 유지한다.

## 적용 명령 — Ubuntu 호스트

실행 중인 주행 launch를 `Ctrl+C`로 종료한 뒤:

```bash
cd ~/AutoVehicle
git pull --ff-only origin final_ws
cd morai_ws/docker/final_ws
bash run_highway.sh stop
bash install_curvature_signal.sh --config
bash run_highway.sh start
bash run_test.sh turn safe
bash run_test.sh speed 35
bash run_test.sh lane on
bash run_test.sh show 2
bash run_test.sh drive 2
```

`lane on`은 이번 기본 보정값을 저장한다. 이전에 직접 조정했던 차선 보정 매개변수도 위 기본값으로 바뀌며 실행 시 안내한다. `show 2`는 실행 명령만 표시한다. 실제 런치는 `final_ws_curvature_signal.launch`이며 `drive 2`가 실행한다.

CAM1 화면 하단의 보정 상태와 `bash run_test.sh diagnose 2`에서 활성 여부, 비활성 이유, 보정 각도, 원본 지연, 신뢰도, 잔차를 확인할 수 있다. 진단은 주행을 켜둔 채 다른 호스트 터미널에서 실행한다. `correction_rad`는 전체 조향 변화율 제한을 적용하기 전의 추가 보정분이다.

비교 주행에서 보정을 끄려면 주행 launch를 종료하고 `bash run_test.sh lane off` 후 `bash run_test.sh drive 2`를 실행한다.

## 확인 범위

코드와 연결 설정을 정적으로 검토했다. MORAI 주행 테스트는 이 작업 환경에서 실행하지 않았다. 실제 좌우 연속 커브에서 보정이 활성화되는지와 중앙선·바깥 차선 여유는 시뮬레이터 주행에서 확인해야 한다.
